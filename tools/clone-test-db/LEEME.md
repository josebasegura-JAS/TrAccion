# Clonar un backup de producción para PRUEBAS

Utilidad independiente; no modifica TrAcción, las preferencias ni la base de producción. El EXE se genera mediante Actions → Herramienta clonar BBDD a PRUEBAS. No requiere Python instalado en el ordenador de uso. Alternativa con Python 3.11 y Tk: python clone_test_db.py.

1. Generar un backup manual desde TrAcción de producción y esperar confirmación. Seleccionar el archivo SQLite terminado, preferiblemente una copia fechada (traccion-backup-*.sqlite, traccion-local-backup-*.sqlite o traccion-shutdown-backup-*.sqlite). No seleccionar el traccion.sqlite activo ni un backup que se esté escribiendo. No usar un respaldo dudoso o procedente de un incidente.
2. Ejecutar TrAccion-Clonar-BBDD-Pruebas.exe. Elegir el backup y una carpeta padre independiente del directorio activo (mismo servidor SMB, permisos restringidos). La herramienta crea una subcarpeta TrAccion_PRUEBAS_fecha_UUID con un traccion.sqlite nuevo. Comprueba integridad, esquema 1–19 e identidad de producción, copia a través de staging local, asigna UUID nuevo y environment=test, elimina editing_locks y verifica contenido e integridad de salida. No copia archivos auxiliares ni configura destinos, no sobrescribe bases. No realiza envíos ni sube datos a GitHub. Los archivos temporales locales se eliminan al finalizar; una interrupción abrupta puede dejar temporales y deben retirarse de forma segura.
3. En el EXE experimental actualizado, entra en Ajustes, selecciona la nueva carpeta (no el archivo) y confirma «Vincular PRUEBAS». La ruta y el UUID se guardan juntos tras validar la base; no se acepta producción ni un UUID inesperado en la misma carpeta vinculada. En el segundo ordenador, selecciona la misma carpeta y confirma.
4. Si usas un EXE anterior a esta mejora, cierra todas las instancias test y renombra únicamente el sqlite-preferences.json del perfil cuyo nombre termina en -entorno-pruebas; después configura la nueva carpeta. No tocar el perfil de producción ni mover/borrar la base anterior.

## Seguridad y alcance
La copia contiene datos personales, históricos y configuraciones reales, no anonimiza nada. Solo usar con autorización y controles de acceso de la organización; proteger tanto el directorio temporal local como el destino SMB; no enviar correos, citas de Outlook, ni documentos a destinatarios reales, y comprobar las rutas de módulos antes de ejecutar acciones externas. La herramienta no altera registros de negocio, salvo metadatos de identidad y bloqueos de edición. La fuente debe ser un backup finalizado y de confianza; integrity_check no demuestra su fecha ni que represente todos los últimos cambios. No se modifica el original; el acceso a red y permisos dependen del usuario. Probar primero con datos ficticios. La validación CI utiliza solo bases sintéticas. No garantiza seguridad ante un administrador que cambie deliberadamente enlaces o permisos durante la copia.
